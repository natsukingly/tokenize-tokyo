## 2. 提出前に閉じる作業

### A. ENS応募のための公開実演を完成させる

担当: 実装・環境設定、実演用ウォレットの操作者。

- [ ] Sepolia用MultiBaasを設定し、必要な9アドレスをlink。DApp read / unsigned compose / Event Query / CORSを確認。
- [ ] 登録済み名前のUniversal Resolverによる実解決と、正しい資産・チェーンへのbindingを最終確認。
- [ ] 公開URLから、実際の登録済みrooftopとissuer/operatorの権限が読める。
- [ ] 屋根への限定委譲 → 許可範囲内の権利提案が成功する。
- [ ] 権限外のinteriorへの提案と、取消後の提案が拒否される。ローカル試験と公開ネットワーク上の確認を区別して記録。
- [ ] 成功tx、取消tx、拒否の理由を審査員が追える形に保存。
- [ ] 提出用公開URLを決める。メインをSepoliaへ切り替える場合は購入・一覧・収益等の回帰確認。ENS用URLを分ける場合は提出文面から両方に迷わず到達できるようにする。

完了条件: **審査員が公開URLでENSv2を用いた空間単位の権限制御を確認でき、コードと証跡にたどれる。**
1つの建物・屋根に絞ってよい。既存の50資産全部を移行する必要はない。
登録済みでない他の名前・`right-N`を実登録として表示しない。

実装手順: [ENSV2_DESIGN.md](ENSV2_DESIGN.md)。ENS公式条件はSepolia、機能するデモ、中核的な利用、公開デモURL、公開OSSコード。前述の委譲・拒否シナリオは本プロジェクトの主張を実証するための完成基準であり、公式が指定した必須シナリオではない。
